# Deploy MetroScan to Render (from GitHub)

Source repo: **vishwa-vup/metroscan-final**, branch `main`
(same app as `metroscan-app` on GitHub, plus the redesigned frontend).
`render.yaml` Blueprint in the repo root wires both services.

## Services created

| Service | Type | URL |
|---|---|---|
| `metroscan-api` | Web Service (Docker, `backend/Dockerfile`) | `https://metroscan-api.onrender.com` |
| `metroscan-web` | Static Site (`frontend/`, `npm run build` → `dist`) | `https://metroscan-web.onrender.com` |

Database stays on **Supabase** (Session Pooler) — no new database needed.
Existing logins (`admin@yourdomain.com`, `inspector123@gmail.com`) keep working.

## Steps

1. **Push** — this repo is already on GitHub (`main` includes `render.yaml`).
2. Render dashboard → **New → Blueprint** → select `metroscan-final` → **Apply**.
3. When prompted, paste `DATABASE_URL` (Supabase Session Pooler URL —
   see `metroscan-render.env` in Downloads, or Supabase → Project Settings → Database).
   `JWT_SECRET` is auto-generated by Render (`generateValue: true`).
4. Confirm `CORS_ORIGINS` = your frontend URL
   (`https://metroscan-web.onrender.com` unless renamed) and
   `VITE_API_BASE_URL` = your backend URL
   (`https://metroscan-api.onrender.com` unless renamed).
5. **Deploy** — first Docker build takes 10–20 min (torch + EasyOCR layers).
6. Verify:
   - `https://metroscan-api.onrender.com/healthz` → 200
   - `https://metroscan-api.onrender.com/health/db` → `{"db":"up"}`
   - Open the frontend URL → Login → Dashboard.

## No-Docker alternative (cheaper/faster)

Backend as **Python 3.12** native runtime instead of Docker:
root dir `backend/`, build `pip install -r requirements.txt`,
start `uvicorn app.main:app --host 0.0.0.0 --port $PORT`,
same env vars. (Same heavy-deps caveat applies.)

## Know before you go

- **Free tier sleeps** after ~15 min idle → first request takes ~1 min.
  Health checks + real traffic keep it warm; use Starter ($7/mo) to avoid sleep.
- **Uploads are ephemeral** without a persistent disk (needs paid tier).
  Reports/evidence in `STORAGE_DIR` vanish on restart unless a disk is attached.
- **Secrets live in Render dashboard → Environment**, never in git.
  Rotate `JWT_SECRET` per environment (Blueprint already generates a fresh one).
- Rename a service? Update the other service's URL env var to match and redeploy it.
